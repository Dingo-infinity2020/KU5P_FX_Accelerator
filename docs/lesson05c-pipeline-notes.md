# 第五课 C：处理流水线优化记录

日期：2026-10-28。按用户要求，本阶段先完成优化和验证，详细讲解留到后续。本文件保存实现选择、复现入口与证据边界。

## 实现选择

- 原第五课已上板的文件保持原样；新增四个 `pipeline` 模块，便于独立重建与对照。
- PFB 四个抽头在四个复数分量上并行乘法，增加乘积寄存器、平衡加法树和输出舍入级。无阻塞时每拍接收一对双路样本；输出阻塞时整个有效流水线保持。
- 三段输入历史按输入握手更新；有效贡献与相位逐级随数据传递。新帧头可以到达上一帧结果仍在流水线中的时刻。
- 历史 RAM 先原样同步读入寄存器，启动深度遮罩放在寄存器之后，避免深度条件破坏 BRAM 推断。单独综合该 PFB 已确认历史使用三个 RAMB36、系数使用四个 RAMB18，零警告；最终仍以完整顶层的综合/实现报告验收。
- FFT 使用相同的 AMD 512 点数学配置，配对输入寄存器允许同拍消费与替换。两核的独立 pending 状态仍保留，不能用两端 ready 的组合生成 valid。
- X 改为乘法、33 位功率/共轭乘积、64 位积分和结果寄存器四级；逐频道存储采用同步 RAM。首帧忽略旧存储，最后一帧结果直接送输出，下一窗口可以继续进入。
- 顶层采用 16 项帧描述 FIFO，将窗口、三种 W、计划范围、epoch/config 和来源送到对应的 FFT 频谱。输入、FFT 完成和窗口结果不再共用一个“等待整帧结束”的控制状态。
- 数学约定不变：4 抽头/相位、512 相位、Q17 系数，FIR 右移 18、FFT 后右移 10，均 ties-to-even 并饱和；相关方向为 `A*conj(B)`。

## 验证安排

完整流水线使用真实 AMD FFT 仿真模型，对照既有独立 Python PFB 整数模型、AMD FFT C 模型及 NumPy 检查。复用原七个数值场景，增加 128 帧吞吐、连续 M=1 窗口和全部无效输入，共十个场景、226 帧。

逐项核对 115712 对 PFB 输出、115712 对 FFT 输出、90 个窗口/46080 行完整 650 位结果。另检查八种协议故障、复位、配置快照、停顿期间数据稳定和结果不被后续窗口覆盖。长堵塞场景要求缓存产生实际反压，并完整排空。

FFT 配对握手另用一个明确标为“非数学模型”的独立测试替身制造 A/B 不同的 ready 节奏；4096 对输出检查顺序、符号、bin/last 和停顿稳定。该替身测试不能替代完整流水线中的真实 FFT 数值验收。

本次完整仿真已经通过上述十个场景。八种协议故障全部被识别；实际出现 37423 拍输出等待、34725 拍 PFB 等待、34667 拍输入等待，最多四帧同时在途，全部参考行被消费且无多余输出。独立 FFT 握手测试通过 4096 对，覆盖 1116 拍两核 pending 不同、2985 次同拍替换和 1329 拍输出等待。

吞吐场景为两路同时各 65536 个复数样本，输出始终可接收，输入在帧头之间持续提供数据。记录第一个到最后一个输入的周期数，以及第一个输入到最后一个结果的总周期数。使用名义 125 MHz 折算速率；行为仿真的 10 ns 时钟用于周期/协议核对，125 MHz 的内部时序以 8 ns 约束的独立实现检查。它们都不代表已在板上产生或测量 125 MHz 时钟。

## 复现

```powershell
./scripts/run_pipeline.ps1 `
  -Python python `
  -VivadoBin D:/AMDDesignTools/2026.1/Vivado/bin `
  -BuildDir D:/work/build/KU5P_FX_Accelerator/lesson05c_pipeline `
  -Route
```

`-PrepareOnly` 生成参考向量、冻结输入哈希并运行独立握手测试；之后可用 Vivado MCP 驱动 `tcl/run_pipeline.tcl` 的 `prepare`，分段运行仿真，再调用 `pipeline_finish 0` 接受数值结果。

MCP 中长构建可用 `pipeline_start_synthesis` / `pipeline_collect_synthesis`、`pipeline_start_route` / `pipeline_collect_route` 分开启动和收集。运行完成状态应同时检查 STATUS 与 PROGRESS；不能以工具调用返回 success 代替新生成的 PASS 标记。构建结束再运行：

```powershell
python -B scripts/pipeline_manifest.py finish --build-dir D:/work/build/KU5P_FX_Accelerator/lesson05c_pipeline --synthesized --routed
```

向量、工具生成的 IP、日志、检查点与 `verification.json` 全部位于仓库外。该清单检查源码/输入哈希、结果数量、吞吐门槛、独立握手测试和新鲜的实现报告。

## 验收边界与下一步

这是两路算法核心的流水线改造。外部持续数据源、整块缓存准入/丢弃、缺失占位和真实网络输入仍是后续工作；输入接口仍允许反压。有限的 128 帧全链路测试用于证明本次优化，不能改称无限时长运行或十六路满带宽验收。

独立模块布局布线只检查内部时钟路径，顶层数据端口没有板级 I/O 时序。OOC 时钟端口尚未绑定实际顶层时钟缓冲位置 `HD.CLK_SRC`，Vivado 对时钟延迟/偏斜给出估计限制提示；这些报告不能代替板级时钟树验收。上板还需引入并验证实际处理时钟、复位、调试观测与板级约束。原有第五课硬件验收记录继续对应原位流。

RFSoC 原始工程继续保留在仓库外。本阶段没有上传原工程，也不包含 RFSoC 配置、网卡驱动或光链路修改。
