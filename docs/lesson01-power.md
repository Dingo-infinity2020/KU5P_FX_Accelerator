# 第一课：让 FPGA 正确处理一串复数样本

日期：2026-10-27。已完成独立参考值、行为仿真和 KU5P 独立综合；尚未上板。

## 1. 这一步解决什么问题

近期先做 FX。若 E=I+jQ 是某个频道的电压，自相关功率为 `E*conj(E)=I²+Q²`。本课先把这段逻辑单独拿出来：

`I,Q → I²+Q² → 累计 M 个样本 → 一个功率总和`

这样可以用几个已知数字检查 FPGA 的数值与数据流规则，先形成完整的“参考值 → RTL → 仿真 → 资源映射”闭环。它不依赖网卡、驱动或尚未提供的厂家网络源工程。

**这只是自相关/功率支路，不能替代送往互相关器的复数电压。** 两路互相关还需要各路的相对相位；未来 FFTT 的空间合成也同样需要保留这些相位。

## 2. 用四个样本看懂结果

配置 M=4，按顺序输入以下同一逻辑流的 I/Q 值：

| 样本序号 | I | Q | 功率 I²+Q² | 已接收样本的功率总和 |
|---:|---:|---:|---:|---:|
| 0 | 3 | 4 | 25 | 25 |
| 1 | 0 | 0 | 0 | 25 |
| 2 | -3 | 4 | 25 | 50 |
| 3 | 1 | 0 | 1 | 51 |

输出为 `power_sum=51, sample_count=4`。平均值是 51/4=12.75，可由后续软件或单独的归一化模块求得；本课输出整数总和，没有加入硬件除法。

这里没有物理单位、小数点或 FFT 归一化假设。RFSoC 和 F 部分的实际标度确定后才能把该整数换算为科学功率。

## 3. 时钟到来，不一定就接收了数据

输入只在上升沿同时满足 `s_axis_tvalid && s_axis_tready` 时计入一次。

- valid：发送方给出了一个可接收的样本。
- ready：本模块有空间接收这个样本。
- 输出未被下游接收时，结果与 valid 保持不变；本实现同时暂停接收新输入。
- 下游接收旧结果的同一拍，可以开始接收下个窗口的首样本。

这组接口只采用 valid/ready 握手约定，不是带完整 AXI 帧/频道元数据的通用 AXI4-Stream 接口。

全部接口与配置属于同一个 `clk` 域；配置必须在该域同步提供。本课没有跨时钟配置或数据通路，不能把异步控制信号直接接到这里。

本模块一次只处理同一个天线/波束、同一个频率频道的连续逻辑流。不能直接把十六路或多个频道交织后喂给同一累加器，否则会混合结果；后续需要独立状态或明确的分组包装层。

## 4. 为什么位宽不能凭感觉选

输入 I/Q 各为有符号 16 位，范围 -32768 到 32767。最小负数的绝对值比最大正数大一，测试必须包含这个边界。

I=Q=-32768 时，功率为 2147483648，即 2³¹。若把结果误当作有符号 32 位，会出现负功率。本实现先做完整 32 位乘积，再以无符号扩展相加，最终在 64 位无符号寄存器中累加。

32 位 M 的最大值为 2³²−1，对当前 16 位输入：

`最大总和 = (2³²−1) × 2³¹ = 9223372034707292160 < 2⁶³`

因此当前合法范围不会溢出 64 位。最大 M 的完整仿真需数十亿次传输；本课验证其配置和未完成窗口行为，并通过上述上界证明数值容量，没有声称跑完这段超长仿真。

未来时间 FFT/PFB 或其他处理会有位宽增长，届时必须重新设计输入/累加位宽或定义缩放，不能无条件截回 16 位后沿用此结论。

## 5. 配置、复位与时间的含义

| 条目 | 当前规则 |
|---|---|
| M=0 | 空闲时拒绝输入，不生成结果 |
| M 生效 | 在每个窗口的首个成功输入传输处锁存 |
| 中途改 M | 当前窗口仍按原 M 完成；新值用于下个窗口 |
| 复位 | 同步低有效；丢弃部分累加和待接收的旧结果 |
| 输出 | 64 位未归一化功率总和 + 32 位样本数 |
| 输入连续时 | RTL 可逐拍接收；不据此宣称已证明板级最高工作频率 |

本课的 M 是“成功传输数”，不是观测时间。仿真中的 valid 间隙是传输停顿，没有给它虚构采样时刻。最终系统还要加入频谱帧号和有效贡献 W，按计划时间窗口积分；真实缺样不能被这个简单计数器隐藏。

## 6. 怎样复现

在 PowerShell 的项目目录运行，显式传入自己的 Python 与 Vivado bin 路径：

```powershell
$python = 'C:\path\to\python.exe'
$vivadoBin = 'D:\AMDDesignTools\2026.1\Vivado\bin'
.\scripts\run_lesson01.ps1 -Python $python -VivadoBin $vivadoBin -Synthesize
```

Python 只需要标准库。脚本默认把产物放在源码仓库旁的 `build/KU5P_FX_Accelerator/lesson01_power`，本机为 `D:/work/build/KU5P_FX_Accelerator/lesson01_power`；也可用 `-BuildDir` 指定仓库外目录。

| 源文件 | 用途 |
|---|---|
| [complex_power_accumulator.sv](../rtl/complex_power_accumulator.sv) | 功率和窗口状态、配置边界、输出寄存器 |
| [generate_lesson01_vectors.py](../scripts/generate_lesson01_vectors.py) | 用 Python 任意精度整数产生独立期望值 |
| [tb_complex_power_accumulator.sv](../sim/tb_complex_power_accumulator.sv) | 驱动输入、随机停顿、检查结果与保持行为 |
| [run_lesson01.ps1](../scripts/run_lesson01.ps1) | 编译、仿真、检查 PASS，再按选项综合 |
| [synth_lesson01.tcl](../tcl/synth_lesson01.tcl) | 算术模块的独立综合与资源报告 |

没有 `-Synthesize` 时只运行参考向量与行为仿真；完整板级 bitstream 构建仍使用 `tcl/build.tcl`。

## 7. 本次实际得到的证据

- 固定种子 `0x4B553550`，169 个 Python 参考窗口，共 10101 个样本；另有专门的复位与非法配置场景。
- XSIM 实际比较 170 个输出窗口，接受 10108 个输入样本；统计包括计划丢弃的部分/待输出窗口。输出反压保持检查经历 65 个停顿周期。
- 检查包含零、正负极值、固定幅度相位轮转、非二次幂窗口、4096 点长累加、随机输入、连续传输、输入间隙、窗口内改配置、M=0、最大 M 的部分窗口、复位清状态。
- 使用 Vivado 2026.1，对已安装 `xcku5p-ffvb676-1-i` 完成独立综合：189 LUT、225 个触发器、2 个 DSP48E2，未使用 BRAM/URAM，没有黑盒。

报告与产物在构建目录：`simulation_pass.txt`、`vectors.json`、`lesson01_power.wdb`、`reports/utilization_synth.rpt`、`reports/timing_synth.rpt`、`complex_power_accumulator_synth.dcp`、`synthesis_scope.txt`。WDB 记录本模块波形，可在 Vivado 仿真波形窗口观察输入握手、累加计数、输出及反压。

独立综合只证明资源映射。10 ns 是检查时设置的目标周期，尚无布局布线和板级 I/O 时序约束；报告存在独立时钟源及端口延迟的适用范围提示，不能用综合 WNS 宣称板卡已在 100 MHz 正常工作。尚未测试实际 RFSoC 数据、网络、跨板相干或真实一秒积分。

仿真开始时曾发现测试驱动在上升沿修改配置与 DUT 采样竞争，已将驱动修改移到下降沿。它说明 testbench 自身也要遵守时序约定，不能把测试程序当作天然正确的证据。
