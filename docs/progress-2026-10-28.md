## 当前 PCIe 阻塞点

板卡位于主机显卡下方的 ×4 电气插槽，当前采用 d5 的 Gen3×4 / 256 位 / 125 MHz 配置，PCI ID 为 `10EE:9034`，VIO 标识为 `465805d5`。d3 已参与一次保持供电的 Windows 重启，配置保留但未建链；d5 在该次启动后才下载，不能把 d5 的观测称为启动历史。

本地复位已释放并读回 0。释放后的两组各 12 点 PHY 读取结果稳定：CPLL/QPLL1 未锁定，GT TX/RX 复位完成标志均为零，PHY rrst_n/prst_n 为 1，但 rst_idle 为 0。训练历史只有 `Detect.Quiet`，Windows 仍无 `10EE:9034`。这些是 PLL/PHY 初始化未完成的实测现象，尚未确定具体根因；缓冲后时钟有活动也不能代替精确测频。

d5 已完成实现：19547 LUT、24451 FF、46 BRAM36 等效块、0 DSP，WNS +1.104 ns；41627 个可布线网络全部完成，22 个引脚与四条 GTY 位置已核对。重复同步引起的 CDC-11 已结构性修正，首轮尝试未上板。最终仍保留原手动复位合并路径的 **1 项 CDC-10 Critical**，已核对两级 FDCE/ASYNC_REG，当前范围仅限长时间保持、单次显式释放的手动调试，尚非生产自动复位方案。

下一步先检查参考时钟频率、PLL reset/power-down 和 PHY 复位状态机，再继续 PCIe 枚举、驱动和已知数据 DMA；FX 结果接入与 100G 外部输入分别在基础链路验收后推进。

## 在 Windows 重建

需要 Vivado 2026.1、Kintex UltraScale+ 器件支持及适用授权。数值参考已使用 Python 3.12.14、NumPy 2.3.5 验证；Matplotlib 仅用于额外绘图，MCP 的可选配置见[专门说明](vivado-mcp.md)。普通构建不要求 MCP。

```powershell
python -m pip install -r requirements.txt
python -B -m unittest discover -s tests -v

# 单元仿真、生成工程、综合实现；产物输出到源码仓库之外。
.\scripts\run_lesson05d.ps1 -Lanes 4 -PhyDebug `
  -Python python `
  -VivadoBin D:\AMDDesignTools\2026.1\Vivado\bin `
  -BuildDir D:\work\build\KU5P_FX_Accelerator\lesson05d_pcie_phy_rebuild
```

该入口不会自动下载固件或操作主机；JTAG 下载/复位使用显式硬件 helper。源码、重建方法与验收边界分别见 [README](../README.md)、[GT/PHY 诊断](lesson05d-phy.md)、[流水线记录](lesson05c-pipeline-notes.md)及[实施路线](implementation-roadmap.md)。本次同步前的 25 项 Python 测试全部通过，Windows 普通文件与模拟端点测试不算真实 PCIe DMA。
