## 2. 这次新增的只读审计

重开 e1 的已保存 routed DCP，检查实际参考网的节点、PIP以及逻辑端口到物理BEL引脚的映射：

- `reference_input` 位于 `GTYE4_COMMON_X0Y0`，目标 common 位于 `GTYE4_COMMON_X0Y1`。
- `body/refclk` 为 ROUTED，路径经过源侧 `CLKOUT_NORTH1` 到目标侧参考输入。
- 逻辑 `GTREFCLK01` 对应物理 BEL 的 `GTNORTHREFCLK11`。逻辑 NORTH/SOUTH 端口常0，不表示实际跨quad专用路径未接通。

因此，**已确认专用北向物理布线路径存在**。不能仅凭bank224/225不同、逻辑端口名或早先手动改NORTH的阴性结果判断原路径非法。这个结果仍不证明外部差分波形、源quad供电或运行时PLL条件正确。

AMD [UG578](https://docs.amd.com/api/khub/documents/BY7rRWkUQliMvNvosLhSZA/content)描述了参考共享、参考输入供电与启动条件。新诊断应遵守GTPOWERGOOD后的使用延时，记录观察链何时有效。现有外部约164µs延时与Wizard内部启动延时需合并审核，不能单凭前者就定为缺陷，也不据此盲加dummy GT。

## 4. 硬件恢复按以下顺序执行

### A. 优先将单通道CPLL测试搬到实板

这是对上一阶段“直接准备Si5338写配置”顺序的调整。已通过动态仿真的5Gb/s/CPLL测试提供了更小的起点，先不用改外部器件状态。

固定原AB7/AB6参考输入、bank225内已核对的一个GT通道、SYS_CLK管理时钟、标准Wizard辅助逻辑，TX保持禁止。加入初始化阶段、管理复位、实际PLL RESET/PD、CPLL lock、TX PMA/helper done与独立活性计数。先仿真、实现、未豁免CDC与重开DCP审计，再作受限SRAM实板对照；e0保持为已验证回退。

建议验收：至少3次独立的局部复位/恢复均成功；每次管理复位及GT初始化序列可核对，CPLL与TX初始化完成后持续观察至少1秒，无资格条件下的失锁。参考计数只在其启动条件满足后采用。测试没有RX数据源，不能以RX数据恢复/BER作为这一步必需门槛。

仿真默认 `C_SIM_CPLL_CAL_BYPASS=1`，所以本步骤也补上硬件校准行为的观察，而不是假设模拟校准已在仿真覆盖。单通道5Gb/s测试不改变正式PCIe目标。

### B. 用结果决定是否引入Si5338对照

| 结果 | 下一项实验/判断 |
|---|---|
| 原参考下CPLL/TX成功 | 再检查同源QPLL1/8Gb/s最小配置；重点比较PLL参数、common选路和复位。CPLL成功不等于PCIe已建链 |
| CPLL成功而QPLL1失败 | 有条件地聚焦QPLL/common差异；仍需独立核对参考频率和各PLL有效范围，不直接定为芯片损坏 |
| 原参考下CPLL也失败 | 准备Si5338本地参考，保持同一GT/CPLL、速率与管理逻辑，改变参考源及必需的选择连接，比较AB7/AB6与V7/V6 |
| 本地源成功、插槽源失败 | 优先检查插槽输入、源quad224条件、输入缓冲与共享路径；不能单独把责任归给主板 |
| 两源均失败 | 重新核对复位/硬件校准/GT供电和厂商最小工程；没有新的正对照前停止堆叠ECO |

本地参考成立的前提是输入、输出与PLL状态经核对；仅写入配置表或看到Si5338 PLL_LOL=0不够。最好有仪器/另一主机/适配本卡与当前插槽的厂商已验证工程中的至少一种正对照。如果两源对照后仍无法区分，应明确需要这些外部证据，不无限增加软件分支。

### C. Si5338必须先有完整配置与恢复方案

目标候选是板载IN3/25MHz输入、CLK2输出适配GT的100MHz差分参考；实际输出电压、格式和共享PLL频率计划审核后才能写。按厂商ClockBuilder/参考手册产生完整频率表及可写掩码，遵循规定的禁用输出、配置、校准和使能顺序，不只修改输入选择位。

现有两份快照只有page0。若配置表涉及page1，必须先备份涉及页的可写字段、原页选择，并验证恢复序列；不能宣称现有快照支持任意完整回滚。**恢复FPGA的e0位流不会自动恢复外部Si5338的寄存器状态。** 回退应分别验收FPGA身份及外部时钟配置/状态。只安排临时RAM配置，不写NVM；共享PLL对其他输出的影响必须明确。

配置与掩码方法依据[Skyworks AN428](https://www.skyworksinc.com/-/media/SkyWorks/SL/documents/public/application-notes/AN428.pdf)，位义依据[Si5338参考手册](https://www.skyworksinc.com/-/media/Skyworks/SL/documents/public/reference-manuals/Si5338-RM.pdf)。不能照搬其他板卡的表，也不能把本地参考直接当作PCIe公共参考来替换。

### D. PLL/GT通过后，恢复PCIe验收

`必需PLL锁定与TX初始化 → PCIe训练进入L0 → 主机枚举 → 兼容Windows驱动/BAR → 已知数据DMA → FX结果DMA`

以从HDL重建的最小XDMA工程为起点，处理现有诊断CDC遗留并验证复位契约。保留显式×4与实际lane映射；必要时先用合法的较低速率配置建立链路，再升Gen3×4。驱动问题可以准备资料，但不将“安装驱动”当作PLL修复方案。

JTAG后主机是否需要再枚举/重启是单独的启动时序问题。[PG213系统启动说明](https://docs.amd.com/r/en-US/pg213-pcie4-ultrascale-plus/System-Bring-Up)讨论了主机供电/JTAG后重启的情形；当前不把重复重启列为每次观测前提。只有建立有效GT条件、需要验证主机启动枚举时，才安排一次有明确固件身份与前后读数的受控启动对照。

## 5. FX学习继续并行推进

PCIe是结果读出通道，不应无限期阻塞算法开发。另一个工作包不依赖RFSoC、网卡或主机驱动：

1. 把优化后的两路流水线在板级目标时钟下实现并验证，从有限回放推进到固定节拍持续输入。
2. 片内源按每路目标100MS/s产生数据，源节拍不因下游ready暂停；先用已知数据核对结果。
3. 加入整帧准入/丢弃、FIFO高水位和缺失记录。制造输出堵塞，核对窗口结束、标签及W_A/W_B/W_AB，不允许用延长窗口掩盖缺失。
4. 用ILA/VIO核对结果与统计，分别做数值验收和长时计数；PCIe接通后替换为DMA读回。
5. 之后验收单口100G的参考/MAC/PCS/FEC/帧接收，再接两路FX；十六路136项相关和真实两板同步在此基础上扩展。

Gen3×4带宽是主机读出预算的约束，不代表FPGA内部FX无法推进；输入原始速率与积分可见度输出应分别预算。两路演示通过后再做十六路资源/带宽验收，FFTT仍为长期目标。
