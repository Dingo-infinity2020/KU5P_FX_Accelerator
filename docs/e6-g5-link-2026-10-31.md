# e6 在 CPU 第一长槽建立 L0 并完成 Windows 枚举（2026-10-31）

## 结论

2026-10-31 在 ASUS PRIME Z790-P 上，把 FPGA 从第二长槽 `PCIEX16(G4)_1`（PCH x4，root port 7A40）移到第一长槽 `PCIEX16(G5)`（CPU x16，root port A70D），加载已验收的 e6 镜像 `465805e6` 并经一次真实 PERST 后：

- LTSSM 进入 **L0**，`link_up=1`，连续 30 s 采样稳定；
- 四路 GT `TX/RX/PMA resetdone=1`，QPLL1 lock=1，RX valid/CDR 正常；
- 协商链路 **Gen3 x4**（Current/Max width=4、speed=3）；
- Windows 枚举到 **`10EE:9034`**（bus1 dev0 fn0），问题码 28 = 未安装驱动；
- BAR、DMA、驱动均 **NOT RUN**。

这是本项目第一次在真实主机上同时取得 **L0 + OS 枚举 + 正确设备 ID**。它同时把此前 e4/e6 在第二长槽的“无 L0”归因从“FPGA/参考/复位入口”收窄为 **该槽位/根端口问题**。

## 硬件拓扑（实测）

| 槽位/接口 | 设备 | 实测链路 | 说明 |
|---|---|---|---|
| `PCIEX16(G5)` CPU x16（第1长槽） | FPGA e6 | **Gen3 x4，L0** | CPU root port A70D；本轮新增 |
| `PCIEX16(G4)_1` PCH x4（第2长槽） | FPGA（历史） | 从未到 L0 | root port 7A40；**可疑槽/根端口** |
| `PCIEX16(G4)_2` PCH x4（第3长槽） | RTX 5060 Ti | Gen4 x4 | root port 7A44；PCH x4 正对照 |
| M.2_2 PCH x4 | NVMe | Gen4 x4 | root port 7A48；PCH x4 正对照 |
| `PCIEX16(G4)_3` PCH x4（第4长槽） | 空 | - | 未测试 |

主板手册确认三个 G4 槽均为 PCIe 4.0 x16 槽（x4 模式），PCH 20 lanes 分配给 3×x4 槽 + M.2_2/M.2_3，未发现 M.2 与 G4_1 的 lane-sharing 禁槽关系。因此：

- “PCH x4 槽不能用”被 GPU/NVMe 的 Gen4 x4 排除；
- “M.2_2 占用导致 FPGA 槽被禁”不获支持；
- **G4_1/root port 7A40 本身**是当前最强嫌疑；同一 FPGA/e6 在 G5 成功，排除 FPGA、参考时钟和 e6 复位入口为主要原因。
- 未记录 BIOS 的 PCIe Spread Spectrum 值；在当前 G5 配置下 `RX_SSC_PPM=0` 仍可建立 L0，SSC 不再作为本轮阻塞项。

## Flash 启动与镜像持久性（新事实）

断电换槽后重新上电，DONE=1，但 e4/e6 的 LTX 都读不到 startup VIO；说明该卡上电会从 **未知 Flash 镜像** 启动，而不是保留 SRAM。当前 e6 是换槽后通过 JTAG 重新加载到 SRAM、再由一次热重启保留的。

- **e6 不是掉电持久的**；断电/关机后回到未知 Flash 镜像，需要重新 JTAG 加载。
- 不写 Flash、不修改未知镜像；后续 H2 测试期间保持供电，或明确记录每次重新加载。
- 原 e4/e6 位流、LTX、DCP 和冻结源均保留在外部构建目录，可回退。
